# AI 共享记忆规范

> `AI_MEMORY.md` 是"AI 首读项目认知入口"，用于快速建立项目心智模型；
> 同时沉淀跨任务、可复用、长期有效的约束与事实。
> 写法以**结论**为准；证据链留在 PR / 提交 / 代码里，不进记忆正文。

---

## 目标

- 让任意 AI 读完后能快速理解项目架构、关键链路和高风险区域
- 避免同类问题跨会话重复排查
- 沉淀可复用的工程约束与边界
- 保持高信噪比：宁缺毋滥，禁止复盘叙事

---

## 写入触发条件（命中任一才写；默认不写）

- 形成了跨模块、以后必须遵守的**约束**（可指导实现 / 审查 / 测试）
- 同类场景还会再踩的**坑位**（根因不直观；只写「触发条件 → 避免方式」结论）
- 确认了长期有效的**事实**或技术边界（框架限制、平台差异等）
- 环境与工具链基线发生稳定变更
- 用户明确要求「以后都按这个做」且可泛化

修了 bug、做了选择、跑通了验证——本身都不够格。  
自检：不写这条，下个会话在决策点会不会再踩？不会 → 不写。  
**禁止**为证明「已验证 / 非显而易见」而写入排查过程、方案对比、验证步骤。

---

## 不写入条件

内容属性：

- 单次任务流水、临时调试、方案对比、决策推演、验证过程
- 拼写 / 文案 / 样式微调 / 单点空值修补 / 一眼能看出的修法
- 函数级实现步骤、魔法数、API 调用次序、代码片段（这些回代码 / PR）
- 未验证的猜测、待确认方案
- 可在 `TASK_MEMORY.md` 追溯的短期任务状态
- 「已修复」状态快照（修完即过期；应压成一句坑位约束，或根本不写）

可达性（命中任一则不写进 `AI_MEMORY.md`）：

- 决策点打开相关文件就能从**现行代码**直接读出同一约束（记忆不重复代码）
- 只存在于一次性调试现场、与当前主路径无关

说明：

- 架构地图 / 关键链路 / 高风险区域：写中层认知（职责与风险），不写实现步骤
- 只写最终约束（以后怎么做），不写「我们讨论了什么 / 怎么验的」

---

## 写入时机

- 确认可复用结论后立即写入（不要等 Stop 催办或压缩）
- 收尾或压缩前：先过删除门槛（见下），再决定是否新增；多数收尾应为「无需落盘」
- 上下文压缩前，只补齐本轮真正命中的长期条目

---

## 删除 / 清理门槛（收尾或压缩前必做）

对 `AI_MEMORY.md` 存量逐条扫，命中任一则删或合并：

- 代码 / 架构已变，条目不再成立
- 条目主要是实现步骤或验证过程，没有可执行结论
- 与架构地图 / 关键链路 / 高风险区域已写内容重复
- 纯「已修复」快照或一次性状态

「定期清理」= 每次命中收尾 / 压缩决策树时做上述扫描，不是另设日历任务。

---

## 写入格式（强制）

```markdown
- **[坑位|约束|事实|平台]** 一句结论。可选一句边界或失败后果。
```

| 分类 | 含义 |
|------|------|
| `坑位` | 易踩陷阱：触发条件 → 避免方式 |
| `约束` | 以后必须遵守的做法 |
| `事实` | 长期有效的架构 / 业务事实 |
| `平台` | 运行时 / OS / 浏览器 / 框架限制 |

技术维（数据、并发等）可写在结论里，**不要**再当主分类枚举。

硬限制：

- 每条最多 **2 句**；超长 → 删过程只留结论，仍超 → 不写
- 禁止复盘动词堆砌（「三个坑叠在一起」「先试了 A 再…」「验证发现…」）
- 证据出处如需标注：一行内点到文件或 PR，不展开过程

正确示例（由修复沉淀，但不写修复过程）：

```markdown
- **[坑位]** 背景未就绪时勿调布局 API；就绪后再延迟一帧执行，纯初始态直接跳过。
- **[约束]** 缩放系数只允许落在 (1.05, 3]；越界必须按「先位置后缩放」回滚。
- **[事实]** 增量构建必须清理已删除源对应的产物，否则旧页残留。
```

错误示例：现象 → 根因论证 → 修法细节 → 验证步骤（无论多「正确」都不进文件）。

---

## 推荐结构（入口型）

1. **项目概览**（业务 + 技术栈 + 入口模块）
2. **架构地图**（页面层 / 状态层 / 核心领域层 / 基础设施层）
3. **关键业务链路**（核心流程的描述和风险点）
4. **高风险区域**（改前优先补读的区域列表）
5. **长期有效规则**（只放上表格式的坑位 / 约束 / 事实 / 平台）
6. **观察中模式**（还不够写成规则的重复信号；见 `continuous-learning.md`）

不单设「已修复」区：能压成一句坑位/约束就进第 5 节，否则不写。

---

## 写入流程

1. **查重**：检索整份 `AI_MEMORY.md`（含架构地图 / 链路 / 高风险 / 长期规则 / 观察中），已有同类 → 合并或跳过
2. **自检**：不写会不会再踩？代码里是否已能读到？会 / 已能读到 → 停止
3. **成形**：压成 `**[分类]** 结论`；删掉排查、对比、验证、实现步骤
4. **归类**：写入「长期有效规则」；不要新开「已修复」类章节
5. **清理**：按删除门槛扫一遍存量
6. **校验**：可执行、可复用、≤2 句；否则不落盘

---

## 责任分工

- 任何人写或改 `AI_MEMORY.md` 都过同一套触发 / 格式 / 删除门槛；Reviewer 不得用复盘正文覆盖结论体例
- 「可沉淀」= 命中写入触发且能压成 ≤2 句；说不清就「无需落盘」
- Orchestrator / 收尾：确认本轮是否命中；未命中明确说「无需落盘」，并做存量清理扫描

---

## 与 TASK MEMORY 的边界

- `TASK_MEMORY.md`：下回怎样接着干（未完成任务）
- `AI_MEMORY.md`：以后类似问题都该怎么做（短结论）

## 完整结构示例（虚构）

以下路径与业务均为虚构，禁止据此去读或创建这些文件。

```markdown
# AI_MEMORY.md — 项目共享认知入口

## 项目概览

- 业务：把本地 Markdown 转成静态站点的命令行工具
- 技术栈：Go + cobra
- 代码主入口：`cmd/root.go`

## 架构地图

### 入口层
- `cmd/root.go` 解析参数并调用构建流程

### 核心领域层
- `internal/build` 负责扫描、渲染、写出

## 关键业务链路

### 链路 A：增量构建
- 扫描源文件 → 渲染 → 写出 → 清理已删除源对应的产物
- 风险点：漏掉被删除的源文件，产物目录残留旧页

## 长期有效规则

- **[坑位]** 读取数据前先确认写入路径，禁止依赖「从未写入过」的字段。
- **[约束]** 并发池任务必须在自身 `finally` 自清理。
- **[事实]** 保存/恢复必须语义对称，存在归一化就必须有逆操作。
```
