# 上下文压缩规范

> 主动压缩、用户手动压缩、系统自动压缩，执行同一套规则。
> 压缩不另建记忆文件。写什么过 `.agents/hooks/memory-write-decision.md`；怎么写见 `.agents/task-memory.md` / `.agents/ai-memory.md`。
> 编排入口：用户说「压缩接着干」「提前压缩」「整理交接」时用 `/context-handoff`。

该接着干的和该长期遵守的，活在文件里，不活在对话历史或压缩摘要里。

---

## 手段选择

先对症，不要按轮次一律压缩：

| 现象 | 动作 |
|------|------|
| 开始漏路由、跳过先读后写、用「应该可以了」收尾 | 再 Read `AGENTS.md` 和当前在改的文件；不立刻 compact |
| 设计谈完要动手、已读大量文件、同一任务还要继续 | 过决策树落盘 → 请用户 compact |
| 阶段切换，或 Cursor 上已经明显漂移 | 过决策树落盘 → 请用户**新开会话**（Cursor 压缩后无重读注入） |
| 排错做到一半、根因还没写下来 | 先把卡点写入 `TASK_MEMORY.md`「阻塞或未决」，再继续；此时不切断 |
| 上下文已胖，但回答仍守规范 | 少读大文件、子任务丢子 Agent；不压 |

仓库**不记录轮次**。1M 上下文下自动压缩很少发生，不要等 compact。命中上表时**建议一次**切断（Cursor 上优先新开会话），由用户确认。独立子任务丢子 Agent。记忆漏写靠写文件脏标记 + Stop 催办，见 `.agents/hooks.md`。

完整模式 Phase 切换（尤其设计 → 实现）按上表「阶段切换」处理。

---

## 压缩前

1. 过本仓库 `.agents/hooks/memory-write-decision.md`（咨询 / 闲聊跳过前置门）。
2. 有未完成、下回要接着干 → 更新 `TASK_MEMORY.md` 四行。
3. 本轮新增且命中长期经验 → 写入 `AI_MEMORY.md`。
4. 未命中条目 → 不写。禁止为了压缩而编一份「压缩记忆」。

不要把交接全文、压缩摘要、操作流水写入 `TASK_MEMORY.md` / `AI_MEMORY.md`。

---

## 压缩后

压缩后的「记忆」= **读已经落盘的文件**，不是摘要本身。

1. **重新读取** `AGENTS.md`，再按 `.agents/task-routing.md` 补读当前任务最小必读
2. **有未完成任务则读取** `TASK_MEMORY.md`
3. **重新读取**当前正在修改的文件
4. **不要凭压缩摘要继续改文件**

Claude / Codex 在 `compact` / `resume` 时会注入一句重读提醒（`.agents/hooks/session-reentry.md`）；Cursor 不注入，压完后用户宜补「重读规范再继续」。权威步骤以本节为准。

### 禁止

- ❌ 压缩后凭摘要猜测之前的决策或代码
- ❌ 跳过重新读取直接继续编码
- ❌ 把压缩摘要再抄进 `TASK_MEMORY.md` / `AI_MEMORY.md`
- ❌ 文件中无记录就丢弃已确认方案、重新规划

---

## 减少窗口占用

- 按需定位读取，避免全量读大文件
- 已确认不改的文件不要反复读
- 独立子任务交给子 Agent，主会话只收结论
- 输出简洁，不要在对话里重复大段文件内容
