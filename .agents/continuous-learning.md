# 持续学习与 Skill 进化

> 何时把重复信号升级为 Skill / 规范 / 长期规则。不是自动改规范。
> 坑和已验证长期规则走 `hooks/memory-write-decision.md` 与 `ai-memory.md`。怎么写 Skill 见 `skills/writing-skill/SKILL.md`。

咨询 / 闲聊 / 无实质性改动：不做模式回顾（与决策树前置门一致）。

---

## 两层不要混

| 层 | 何时 | 写哪里 |
|----|------|--------|
| 可压成 ≤2 句的坑位 / 约束 / 事实 / 平台 | 第一次就能写成可执行结论（无复盘、无验证过程） | `AI_MEMORY.md` 长期规则或对应规范（决策树） |
| 还不够写成规则的重复信号 | 像、但还没抽象 | `AI_MEMORY.md`「观察中模式」；达阈值进通知区，**问用户**再固化 |

不要把第一次踩坑先记成 `[1/2]` 观察项——能写成短结论就直接进长期规则；写不短就「无需落盘」，不要用长复盘硬塞。

---

## 观察中模式

只在有实质性改动的收尾、且出现下列信号时更新。不要每个任务都输出 `【模式回顾】`。

格式（只在本文件维护；`AI_MEMORY.md` 只放条目）：

```markdown
- **[N/阈值] [信号类型]：[一句话描述]**
  - 最近出现：[日期]（[任务简述]）
  - 特征：[关键共性（可选）]
```

| 信号类型 | 阈值 | 计数什么 |
|----------|------|----------|
| 同类 bug | 2 | 同一类缺陷反复修，尚未抽成规则 |
| 同类任务 | 3 | 同一种工作流反复手搓，可能抽 Skill |
| 规范绕过 | 3 | 同一条规范被忽略，规范可能不合理或缺拦截 |
| 技术栈变更 | 1 | 稳定引入新工具/框架（先问要不要补规范，**默认不新建 Skill**） |

命中已有条目 → `N+1` 并更新「最近出现」。没有对应条目再新增 `[1/阈值]`。

达阈值：

1. 把该条复制到 `AI_MEMORY.md`「持续学习通知区」
2. **当面向用户说明**建议固化成什么（长期规则 / 改哪份规范 / 是否新 Skill），等确认
3. 不要在未确认时改规范或新建 Skill

连续 6 个有实质性改动的任务未再出现 → 标 `（待清理）`，下次维护删除。用户否定「这不是模式」→ 直接删。

---

## 用户确认后怎么固化

- **长期规则** → `ai-memory.md`（一句结论）。不要再走下面流程。
- **规范微调 / 纠错** → `spec-governance.md` 修改检查清单。
- **新 Skill 或规范重大新增** → 先用本段；写 Skill 时读 `writing-skill`（没有失败基线或重复证据就不要写）。

1. 用 2–3 句话说清不变部分和因场景而变的部分
2. 指定唯一落点（一个 Skill 或一份规范），禁止同一条抄进多处
3. 用户点头后再写入，并同步 `spec-index.md` / `skills.md`（不要把路径清单写进 `AGENTS.md`）

「新工具引入一次」只够提示要不要补语言规范，不够单独开 Skill。

---

## 禁止

- ❌ 无实质性改动也做模式回顾
- ❌ 未达阈值、未经用户确认就改规范或新建 Skill
- ❌ 把一次性问题写成长期规则或 Skill
- ❌ 用 Loop 定时刷观察项
- ❌ 要求「换一个 agent 再跑一遍才算验证」
