# Git 工作流规范

---

## 何时提交

只在用户**本轮明确说**「提交」「commit」「提交代码/更改/修改」时执行 `git commit`。

不构成授权：

- 任务做完、验证通过、可以交付、收尾、结束会话
- 本会话里上一轮已经帮用户提交过
- 编排流程走到 Phase 5 / 交付检查

未要求时可以在回复里提示「需要的话我可以提交」，不要自己跑 `git commit` / `git add`。`git push` 仍须另一次明确要求。

---

## 分支管理

先看仓库实际策略，不要套默认 Git Flow。

确认方式：远程默认分支（`origin/HEAD` 或托管平台设置）和已有分支命名。没有的分支不要造。

| 种类 | 说明 |
|------|------|
| 受保护主干 | 常见 `main` / `master`，有的仓库还有 `develop`。禁止直接推送 |
| 功能 / 修复分支 | 从**当前仓库的默认分支**切出。已有 `feature/*`、`fix/*` 等约定则跟随 |

## Commit Message 格式

遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范。

```text
<type>: <description>
```

| 类型 | 用途 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 bug |
| `refactor` | 重构（无功能变化） |
| `docs` | 文档更新 |
| `test` | 测试相关 |
| `chore` | 构建/工具链 |
| `perf` | 性能优化 |
| `ci` | CI/CD 配置 |

- 描述使用中文，控制在 50 字以内
- 单次提交只包含一个逻辑变更
- 用 HEREDOC 传 `-m`，避免中文引号把 shell 切断
- 文风可参考 `git log -5 --oneline`，type 仍按上表

```bash
git commit -m "$(cat <<'EOF'
docs: 说明提交信息用 HEREDOC 传递

EOF
)"
```

## 变更拆分规则

提交前必须先按文件和变更目的判断是否需要拆分。命中任一信号即应拆分为多次提交：

| 信号 | 说明 |
|------|------|
| 多个不相关目的 | 同时包含功能新增、bug 修复、样式调整、文档更新等不同目的 |
| 多个独立模块 | 变更跨越无直接依赖的模块，可独立交付 |
| 混合 type | 变更需要不同 commit type，如 `feat` + `fix` + `docs` |
| 可独立回滚 | 某部分变更有独立价值，应能单独 revert |

拆分执行规则：

- 每次提交只 stage 当前组文件，禁止 `git add .`
- 必须列出 untracked：属于本次逻辑的不能漏；`.env`、密钥、构建产物、用户未确认的文件不能加
- 按依赖顺序提交：类型定义 / 底层逻辑 → 上层组件 → 测试 / 文档
- 每组提交都必须单独确认 type 和 description
- 不确定是否同一逻辑单元时，默认拆分或先问用户

## Pull Request 流程

1. 从最新**默认分支**切出（不要假设一定是 `develop`）
2. 完成功能并跑仓库已有验证
3. 对默认分支（或项目写明的集成分支）提 PR，填写变更内容和测试计划
4. Code Review 通过后合并

未要求创建 PR 时，不要自行 push。

---

## 质量门禁

只跑仓库已有的验证命令；没有对应命令则跳过并在提交说明里写明。

| 场景 | 处理 |
|------|------|
| 项目已配置的 lint / 类型检查有 error | 不得提交，必须修复 |
| 项目已配置的 lint 仅有 warning | 可提交，须在交付说明里写明；若 pre-commit hook 会因 warning 失败则先处理 |
| 没有类型检查 / lint / 测试 | 跳过该项，不要为迁就本表去安装工具 |
| 当前分支 CI 已失败 | 不阻止本地 commit；不要再 push / 合入，先修 CI |

---

## 禁止事项

- ❌ 未明确要求时禁止 `git commit` 和 `git push`（任务完成 / 收尾 / 本会话曾提交过，都不算要求）
- ❌ 禁止直接推送受保护主干
- ❌ 禁止大而全的提交
- ❌ 禁止提交临时调试语句（JS/TS 为 `console.log` 等；按仓库语言检查，不要套用其他语言的命令）
- ❌ 禁止提交 mock 数据或临时测试数据（开发环境自用除外）
- ❌ 禁止 `--no-verify` 跳过 pre-commit hook
- ❌ 危险操作（`reset --hard`、`push --force`、`git rm`）必须先询问用户确认
