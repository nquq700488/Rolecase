# Frontend Design

> 负责 UI 视觉方向和体验质感。不替代需求方案，也不替代实现后的合规 / 代码审查。

## 铁律

```text
没有视觉计划（完整或轻量）不要写 UI。
已有设计系统时先跟系统，再谈个性。
```

## 必读规范

1. `AGENTS.md`
2. `.agents/coding-standards/css.md`（写样式或组件内样式时）

实现后合规用 `web-design-guidelines`；代码质量用 `code-review`。本文件不复制它们的条目。

## 使用边界

使用：新建或重塑页面/组件、活动页、作品集、产品展示、高保真；用户说「设计一下」「优化界面」「高级一点」「不要模板感」；视觉方向未定但即将编码。

不使用：纯逻辑 / 数据流 / 接口；需求范围和交互路径未定 → `solution-brainstorm`；已实现页的 a11y / 响应式 / 表单合规 → `web-design-guidelines`；代码审查 → `code-review`。

## 完整还是轻量

**轻量版**（同时满足才走）：不改色彩体系、布局骨架、组件形态；只动局部色/间距/状态。输出：界面类型、变更意图、受影响的色/间距/状态、反模板一句。不要重建色板和 signature。

**完整版**：新建页面、视觉重塑、用户明确不要模板感，或会改色彩/布局/组件形态。必须先交视觉计划，通过反模板后再编码。

缺口影响设计质量时再问用户：服务谁、展示型还是操作型、首屏主信息、是否已有品牌/组件库、有没有参考图或竞品、哪里密哪里留白。能从上下文回答的不要问。无参考时先问，禁止凭空造「高级感」。

## 视觉计划（完整版输出契约）

编码前只输出这一张卡片，不要写成小作文：

```text
【视觉计划】
界面类型：展示型 / 内容型 / 操作型 / 数据密集型
设计目标：一句话（感受或效率）
取材：产品领域物料 / 仓库已有界面 / 用户参考（写明来源；都没有则先问）
差异点：这页和通用 SaaS 不同的那一处，以及为什么属于这个产品
颜色：4–6 个命名色（背景、文本、主行动、强调、边框/分隔）；有设计系统则引用 token，不另造色板
字体角色：至少标题 + 正文（不能只写「默认 sans」）
布局：网格、信息层级、导航/工具区
signature：一个能记住的视觉元素（不是通用渐变卡片）
文案：按钮/空态/错误用任务用语，不用 Unlock、赋能、无缝体验
交互原则：hover / focus / active / loading / empty / error
操作型附加：密度可扫描、控件位置稳定、无 hero/营销构图、卡片不套卡片
```

操作型界面：安静、紧凑、可扫描；不要做成营销 landing。

## 必守红线

- 取材或差异点空着 → 未过反模板，不要编码。换成任意产品名仍然成立 → 太泛，改计划再编码。
- 禁止默认蓝紫渐变、深色玻璃、米色极简、深蓝 slate、棕橙咖啡；也禁止下一套默认：奶油衬线+陶土、黑底酸绿/朱红、报纸细线三栏。
- 禁止装饰 orb / bokeh / 无意义插画、单色铺满。
- 首屏呈现产品或任务本身，不要营销口号；界面文案用用户能认出的任务语言。
- 网站/游戏用真实视觉资产；产品/场所/人物/物件主体在首屏可见。
- 不靠视口宽度缩放文字；不用负字距；固定格式控件尺寸稳定。
- 图标跟已有图标库；动效只服务状态和空间关系（细则见 `web-design-guidelines`）。
- 落实计划后再交；实现了页面则接着跑 `web-design-guidelines`。
