# 项目初始化（Onboard）

> 本 skill 负责项目首次接入规范体系时的初始化工作。
> 不替代 `solution-brainstorm` 的功能设计；只生成规范框架和初始记忆。

---

## 执行卡片

必须：

- 检查现有规范文件是否存在
- 不覆盖已有用户文件
- 规范文件缺失只记录并在报告中提示，不擅自生成整包
- 仅当 `AI_MEMORY.md` 不存在时，用仓库里能直接读到的信息生成空框架初稿

禁止：

- 覆盖已有项目文件
- 猜测业务逻辑或架构细节
- 用户未要求时创建 CCB 配置
- 执行 git commit

输出：

- 输出已存在、已创建、缺失待补齐三类清单

---

## 触发时机

- 用户说"初始化项目"、"接入 AI 规范"、"onboard"、"设置项目"
- 新项目首次使用本规范体系
- 现有项目规范文件缺失或损坏需要重建

---

## 必读规范

1. `AGENTS.md`
2. `.agents/task-routing.md`
3. `.agents/ai-memory.md`（记忆写入规则）

---

## 执行骨架

### 步骤 1：检查现有规范完整性

检查 `.agents/spec-index.md` 列出的规范文件是否存在。另外确认：

```text
AGENTS.md
CLAUDE.md
CURSOR.md
AI_MEMORY.md
TASK_MEMORY.md
.cursor/hooks.json
```

- **已存在** → 跳过，不覆盖
- **规范文件不存在** → 记入报告的缺失项，提示用户补齐；不自动生成规范正文
- **`AI_MEMORY.md` 不存在** → 进入步骤 2；已存在则跳过步骤 2

### 步骤 2：仅在缺失时生成 AI_MEMORY.md 初稿

只填能从仓库直接读到的项（语言、清单里的入口路径、已有验证命令）。读不到的留占位，不编业务故事。独立使用时可用下面结构：

```markdown
# AI_MEMORY.md — 项目共享认知入口

## 项目概览

- 业务：[一句话描述，不确定则留空]
- 技术栈：[从仓库配置读取；读不到则留空]
- 代码主入口：[入口文件 / 入口目录]

## 工程基线

- 运行时 / 语言版本：[以仓库已有版本文件为准]
- 包管理 / 构建：[以仓库已有工具为准]
- 常用验证命令：[实际存在的命令]

## 架构地图

<!-- 按实际代码分层；不适用的层删掉 -->

### 入口 / 表现层
### 状态 / 数据层
### 核心领域层
### 基础设施层

## 关键业务链路
## 高风险区域
## 长期有效规则
```

### 步骤 3：检查 CCB 配置（默认只查不建）

- 检查 `.ccb/ccb.config`、`.ccb/ccb-compact.config`、`.ccb/ccb-multi.config`、`.ccb/README.md` 是否存在
- 缺失 → 记入报告，**不要创建**
- 仅当用户明确说要接入 / 启用 CCB 时，才按 `.ccb/README.md` 的三文件 profile 模式补模板

### 步骤 4：检查 .claude/commands/

检查目录是否存在、是否已有 skill 路由文件。缺失记入报告；不擅自批量创建。

### 步骤 5：输出初始化报告

```text
【项目初始化完成】

已检查的文件（规范正文缺失只记入待补，不擅自生成；仅 `AI_MEMORY.md` 缺失时可生成空框架）：
✅ AGENTS.md（已存在 / 缺失待补）
✅ AI_MEMORY.md（已生成初稿 / 已存在）
...

待用户手动填充：
- AI_MEMORY.md「项目概览」和「架构地图」（若本次生成了初稿）
- 技术栈对应的语言规范文件
- CCB 配置（仅当用户要求启用多模型时再补）

建议下一步：
- 让 AI 读取 AI_MEMORY.md 并帮助完善架构地图
```

## 必守红线

- 不覆盖已存在的用户自定义文件（询问用户是否覆盖）
- 不替代 `solution-brainstorm` 的设计工作
- 只生成 `AI_MEMORY.md` 空框架，不猜测业务逻辑或架构细节
- 用户未明确要求时，不创建 CCB 配置
- 不执行 git commit（初始化完成后由用户决定是否提交）
