# Solution Brainstorm

> **硬门禁**：完整模式、高风险或需求不清的创造性工作，在呈现设计并获得用户批准之前，不得调用实现 skill 或写代码。
> 轻量任务一句话说清改什么即可继续。

## 执行卡片

必须：先判断模式；完整模式先澄清目标/范围/非目标/验收；模糊需求列出假设，两种以上合理解释时先给选项；用户批准后才进入实现。

禁止：在本 skill 内写实现代码；未确认就声称设计完成；多模型首轮观点后直接定稿；为未确认的未来需求加扩展点。

输出：方案摘要、任务拆解、待用户审核点。

---

## 两种模式

| 模式 | 适用 |
|------|------|
| **A 一对一**（默认） | 完整模式、高风险或需求不清 |
| **B 多模型** | 用户明确要求、全链路、跨模块高风险 |

从 A 开始。`agent-workflow` 的 P0 **只跑模式 A**。模式 B 只由 `multi-agent-orchestrate` 的 P0 主持，或用户一开始就要求多模型头脑风暴（此时不要进入 `agent-workflow`）。不要在本地流程中途切到模式 B。

必读：`AGENTS.md`、`task-routing.md`、`planner.md`；多角色时加 `agent-registry.md`；模式 B 加 `collaboration.md` 与 `.ccb/ccb.config`。

---

## 模式 A

1. 读相关文件、文档、最近提交，不猜。
2. 多个独立子系统 → 先拆子项目，只对第一个进入设计。
3. 一次只问一个问题；优先选择题。宽泛目标先明确成功标准和边界。
4. 给 2–3 个方案 + 权衡 + 推荐；最简单可验证方案必须在列。
5. 按节确认：架构 → 模块 → 数据流 → 错误处理 → 测试策略。
6. 呈现前自检：完整性、验收覆盖、任务可执行、歧义、反过度设计、逐行可追溯。跨会话需要时写入 `TASK_MEMORY.md`。
7. 请用户审核：背景、范围/非目标、方案、验收、实现清单（结构见 `planner.md`）。未批准不算完成。
8. 过渡：A → `agent-workflow`；B → `multi-agent-orchestrate`。本 skill 内不编码。长设计对话结束后按 `.agents/context-compression-guidelines.md` 手段表建议切断再实现。

---

## 模式 B

CCB 不可用 → 按 `collaboration.md`「不可用即报错」，不降级本地多角色。角色视角见 `agent-registry.md`，本文件不重复。每轮 prompt 注入 `【身份设定】` + `【角色规范】`。

| 轮次 | 目的 | 输出 |
|------|------|------|
| Round 1 独立发散 | 防从众 | 各角色独立方案/风险/替代路径 |
| Round 2 交叉挑战 | 碰撞 | 对其他观点的支持/反对/补充/待验证 |
| Round 3 收敛 | 共识 | 修订、保留意见、共识确认 |

- 首轮并行；首轮后不得定稿，至少进 Round 2
- 交叉挑战最多 3 轮；一轮无新高价值分歧即停
- Round 3 后仍有方向性分歧 → 选项 + 代价 + 默认建议，交用户裁决
- 有 agent 不可用 → 报错停止，不降级单视角

```md
## 多模型头脑风暴共识
### 共识方案
### 采纳记录（来源 / 观点 / 裁决 / 理由）
### 少数意见
### 未决问题（无则写"无"）
### 定稿动作
```

共识后走模式 A 步骤 6–8。

---

## 必守红线

- 完整模式在用户批准前不得进入实现；轻量任务仍须一句话说明意图。
- 只有最外层 Orchestrator 可启动本 skill；子 agent 不得递归启动。
- `inspiration` 只提供补充视角，不代执行其他角色。
- 模式 B 首轮观点 ≠ 完成；大项目先拆子项目再设计。
