# 规范治理（唯一来源）

> 目的：避免规范重复、职责漂移、入口分叉。
> 原则：一类规则只保留一个权威来源，其他文件只摘要或链接。

## 新增规范前检查

- 先判断现有文件是否已有同类职责，避免新增重复源
- 若只是补细节，优先修改原文件，不新建
- 新文件必须能回答”它是某类规则的唯一来源吗”
- 若不能成为唯一来源，不应新建
- **规则的新增和重大修改**：先有重复证据或用户明确要求，再按 `continuous-learning.md` 征求确认后写入；**微调纠错**走本文档的修改检查清单

## 修改规范时检查

- 同一条规则是否已在别处完整出现
- 新增内容是否越过当前文件职责边界
- 入口文件是否只保留摘要，不复制正文
- 交叉引用是否改为链接，而不是再次展开

## 写作与维护准则

- 规范读者是 Agent，优先约束表达，避免教程化叙述
- 同类规则只保留一处完整正文，其他文档只链接
- 示例最小化；必要时用“正确/错误”对照
- 结构保持扁平，避免多层嵌套导致读取成本上升

## 分层与目录

规范按 `common` + 语言/领域特定分层时：

- **优先级**：语言 / 样式特定规范 > 通用层（类比 CSS 特异性）；详见 `coding-standards/common.md`「优先级」。
- **相对引用稳定**：语言特定文件用相对路径引用通用层，移动文件时同步修复，不留断链。
