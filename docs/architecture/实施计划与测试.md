不做完整 UI，只验证架构假设：

- Claude ACP Adapter 启动；
- Codex ACP Adapter 启动；
- initialize 握手；
- API Key 和本地配置；
- 自定义 Base URL；
- 模型、effort 和权限能力发现；
- 创建 Session；
- 流式事件；

- 权限请求不应答时的软提醒与硬超时拒绝/取消；

- Claude `CLAUDE_CONFIG_DIR` 和 Codex `CODEX_HOME` 隔离效果；
- 取消；
- 崩溃清理；
- 两个 Session 使用不同 Model；
- 使用锁定版本运行同一套 Contract Test，不依赖全局 npm 安装或临时目录脚本。

验收标准：两个 Provider 都能完成“配置 → 连接测试 → 单轮对话 → 权限应答 → 事件回显”，并通过取消、恢复、隔离和崩溃清理测试。

- `tests/contract` 的 Fake ACP 与真实 Adapter 参数化测试；
- 真实 Provider 缺少凭据时只能记录为环境阻塞，不能将“跳过”计为 Phase 0 通过；
- Codex isolated 空目录返回 `needs_configuration` / `Authentication required` 时不得静默回退 inherited。

Phase 0 实际验收记录（2026-10-14）：

- `pnpm -r typecheck`：通过；
- `pnpm test`：Contract / Server / Fake ACP 测试通过，真实 Adapter 用例默认跳过；

- Provider 环境配置闭环 Batch A/B 已完成：Web Provider 页支持 provider kind / connection kind / environment mode / 非秘密 base_url / credential_ref 输入，按组合判定展示 ready / 待配置 / 待导入 / 认证未验证，Codex 配置导入提供「受控服务器路径 → 脱敏 preview → 确认 apply」；凭据创建已由 Phase 1E 补齐，仍不提供 OAuth 或浏览器文件选择；
- Provider 环境配置闭环 Batch A 已完成：组合规则 `resolveProviderCombination`（ready / needs_configuration / invalid / unverified）、Claude custom endpoint 经 `ANTHROPIC_BASE_URL` 生效、Codex custom endpoint 认证未证一律 `codex_custom_endpoint_unverified`、三入口统一的 spawn 前闸门；
- 凭据边界复核修复已完成：`security -w` 双行 stdin 写入、公共凭据值校验（拒绝行分隔符）、Keychain exit code 优先分类、`inherited + credential_ref` 显式拒绝、短生命周期 `SecretRedactionScope`（跨 chunk 流窗口、按 `text` 字段与 owner 还原/丢弃尾部）、ACP 成功响应与错误（含顶层数组）脱敏、stdio 半关闭与异常退出的统一幂等清理、number/string 同值权限请求 ID 冲突 fail-closed、关闭时收敛 pending permission；

## 3. 质量门槛

- 单元、集成测试必须存在；本计划**不新增 E2E runner**，浏览器验收使用现有 Playwright MCP 手动执行（局部例外，不改变其他阶段的通用要求）；
- 核心模块覆盖率目标不低于 80%；
- API 和 Adapter 升级必须先通过契约测试；
- Port Contract Test 必须覆盖 `resumeSession`、权限应答、取消和资源清理；
- 不用固定等待时间判断异步完成，使用事件和状态断言；
- Web UI 手工验收覆盖 320、375、768、1024、1440、1920 六个 viewport；不新增 `@playwright/test`、`test:e2e` 或浏览器下载；
- 必须测试键盘操作、错误状态和 reduced-motion；
- 必须验证无溢出、无明显布局跳动和密钥脱敏。

## 4. 风险与缓解

### ACP Adapter 版本变化

锁定精确版本、记录 Adapter 版本、维护契约测试和回滚方案。

### Claude ACP 与 Claude CLI 路径不同

把 ACP Adapter 视为独立 Runtime，不假设它能复用 CLI 的全局配置。

### 全局配置污染

默认 `inherited` 以兼容已有本地 CLI 登录态；启用 `isolated` 时，运行时目录由 Rolecast 派生，ProviderConnection 成为唯一配置权威，配置只通过 API key 的 `credential_ref` 提供。Codex 只允许导入非秘密配置草稿并由用户确认，不能复制登录态文件、整份配置目录或静默回退到全局环境。CC Switch 只做参考或导入。

### Localhost 控制面被网页滥用

绑定 127.0.0.1，使用 Local Token，校验 Origin/Host，REST/WS 全部认证。

### 权限请求导致 Agent 挂起

权限请求必须进入 Web UI，支持 5 分钟软提醒、默认 30 分钟硬超时、拒绝、取消和恢复。硬超时标记 `PermissionRequest.expired` 与 `Run.interrupted`，不自动批准或重跑；服务重启后按持久化时间戳恢复计时。

### 上下文无限增长

使用 Context Builder、Session 摘要、Artifact 引用和最小上下文原则。

### 运行状态和历史混淆

Rolecast 自己持久化 Run、Task、Event 和 Artifact，不只保存活动 Run 快照。

### 许可证和闭源依赖

只复制设计；记录第三方来源；Adapter 作为外部运行依赖；分发前进行许可证审核。
