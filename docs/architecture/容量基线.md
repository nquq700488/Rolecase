## 4. 测量方法与未覆盖行为

**当前脚本实测（仅合成 SQLite + 纯策略）：**

1. **环境记录**：Node/OS/架构、CPU/内存、SQLite 版本、实际启用的 `journal_mode` 与 `foreign_keys`；不声称未显式设置的其他 PRAGMA。
2. **Q**：批量填充 `tasks.status='queued'` 行；用真实 `COUNT` 作为 `used`，分别观测 `used=limit-1, requested=1`（接受）与实际增加到 `used=limit, requested=1`（拒绝）；记录 seed/count/decision 耗时、行数、DB/WAL 字节和共享进程 RSS 快照。
3. **P**：批量填充 `permission_requests.status='pending'` 行；使用真实 `COUNT` 做同样的边界判定并记录相同观测。
4. **N**：只验证调用方预先计算的总节点数整数边界（`limit-1` 接受、`limit` 拒绝）；不遍历 DAG 或嵌套结构。
5. **重复**：每点 3 次，独立临时 SQLite；运行内自检要求 `COUNT` 与注入点一致且边界判定符合预期，否则脚本以非 0 退出。

**后续未实现验证（不属于当前 0C 脚手架证据）：**

- Fake ACP 多 Adapter 满额调度与名额释放、并发的生产式 admission；
- 达到 P 时的 deny 事件、Permission 中断与自动 approve 禁止行为；
- 重启后从持久化状态重建队列/权限计数；
- Template/Run 节点模型的结构遍历、防绕过与 N admission；
- 真实 Adapter 进程树/OS 资源或生产容量、SLO 保证。

结果只代表该参考环境与合成 SQLite 负载，不是任意生产机器保证，也不构成用户对 Q/P/N 的批准。

## 5. 0C 本机观察报告（2026-10-30）

### 环境与方法

- 采集时间：`2026-10-30T08:30:53.424Z`。
- 参考机：Node `v22.21.1`，`darwin` / `arm64`，macOS `25.5.0`；Apple M2、8 CPU、16 GiB RAM。
- 存储栈：`better-sqlite3 11.10.0`、SQLite `3.49.2`；`journal_mode=wal`、`foreign_keys=1`。测量代码只显式设置这两个 PRAGMA；不对其他默认设置作额外声明。
- 输入：Q/P/N 各自注入 `[16, 64, 256, 1024, 4096]`，每点重复 3 次，共 45 次测量。每次使用独立临时 SQLite；这些点仅用于实验，不是额度候选。
- Q/P 对各自表插入 `point-1` 行，执行真实 `COUNT`，再插入 1 行并再次 `COUNT`；low / at-limit 判定的 `used` 分别来自实际计数。`seed_ms` 包括填入前 `point-1` 行及补入最后 1 行；`count_ms_low` / `count_ms` 分别是两次 COUNT 时间；`decide_ms` 是两次纯策略判定的合计时间。N 仅将 `point-1` 与 `point` 作为预计算整数输入，不创建节点、不遍历图。
- 下表时间为毫秒：seed 显示 3 次重复的中位数（括号为最小–最大），COUNT 显示 low / at-limit 中位数；N 显示两次判定合计的中位数。原始时间记录保留 6 位小数，资源字节数为逐次记录值。

## 6. 风险

- 队列/权限/节点上限过低会降低可用性；过高会放大内存/文件描述符/权限等待风险。
- Adapter subprocess 的资源开销高于纯 SQLite 行；Q/P/N 不能仅由 SQLite 行操作推导。
- 本次测试注入值若被误读为生产配置，会形成未经批准的容量承诺；文档与配置必须严格区分。
- 重启恢复时现存负载可能超过批准额度：必须保留现场并停止新 admission，不能删数据腾额。
