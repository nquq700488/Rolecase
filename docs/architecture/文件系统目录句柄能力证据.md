# 文件系统目录句柄能力证据（Stage 0）

> 状态：**研究结论，未引入依赖、未修改代码。**
> 目标：证明或否定 Node 22 / macOS 上可用的 pinned directory handle / dirfd-relative、逐组件 no-follow 文件操作能力，作为 Artifact 文件写入的实施门。

---

## 1. 结论（先行）

**无法在当前允许范围内证明所需能力。**

- Node.js 22 核心 `fs` 模块只提供路径式 API；没有 `openat`/`renameat`/`unlinkat`/`mkdirat`/`fstatat`。
- `fs.opendir()` 返回的 `Dir` 不暴露目录 fd；`fsPromises.open(dir, O_DIRECTORY|O_NOFOLLOW)` 可获得 fd，但 `FileHandle` 只有 `read/write/stat/...`，不能以该 fd 为基准 create/rename/unlink 相对路径。
- 仅用 `realpath` + 绝对路径 I/O 无法封闭「校验后父组件被替换为 symlink」的 TOCTOU 窗口，不能作为安全 fallback。
- 受维护的 native 候选（如 `@openclaw/fs-safe`、`@cocalc/openat2-*`）未安装、未在本机验证 macOS 语义；Stage 0 禁止安装依赖或尝试 native addon。
- **因此 Artifact 文件写入保持 fail-closed；Stage 2 文件路径不得进入实施。** 该结论不阻断 SQLite inline Artifact（不做文件系统操作，但仍要求有效 `root_path`），也不阻断当前已交付的 Phase 2 handoff。

## 2. 本地 Node 22 实测证据

环境：`node v22.21.1` / `darwin` / `arm64`（本机执行，2026-10-27）。

```text
  console.log(['openat','renameat','unlinkat','mkdirat','fstatat'].map(n=>n+':'+typeof fs[n]).join(' '))"

openat:undefined renameat:undefined unlinkat:undefined mkdirat:undefined fstatat:undefined
```

```text
$ node -e "const {opendir}=require('node:fs/promises'); (async()=>{const d=await opendir('/private/tmp');
  console.log('Dir', d.constructor.name, 'own keys', Object.keys(d), 'has fd', 'fd' in d); await d.close()})()"
Dir Dir own keys [] has fd false
```

```text
$ node -e "const fs=require('node:fs'); const {open}=require('node:fs/promises');
  (async()=>{const h=await open('/private/tmp', fs.constants.O_RDONLY|fs.constants.O_DIRECTORY|fs.constants.O_NOFOLLOW);
  console.log('fd', h.fd, Object.getOwnPropertyNames(Object.getPrototypeOf(h)).filter(n=>typeof h[n]==='function').sort().join(',')); await h.close()})()"
fd 11 appendFile,chmod,chown,constructor,createReadStream,createWriteStream,datasync,getAsyncId,read,readFile,readLines,readableWebStream,readv,stat,sync,truncate,utimes,write,writeFile,writev
```

观察：

1. 目录 fd 可以打开，但没有任何「相对于该 fd」的 open/create/rename/unlink 方法。
2. `/tmp` 在 macOS 是指向 `/private/tmp` 的 symlink；带 `O_NOFOLLOW` 打开 `/tmp` 失败（`ENOTDIR`），打开 `/private/tmp` 成功。说明 no-follow 只作用于最终组件，不能替代逐组件锚定。
3. `fs.rename`/`fs.unlink`/`fs.writeFile` 均为路径式，父组件在校验后仍可被替换，形成 TOCTOU。

## 3. 外部资料核对

- Node.js 官方文档的 `fs`/File descriptor 章节只描述路径或 `file:` URL 打开；fd 仅用于 `read/write/close`，没有 dirfd-relative 操作（https://nodejs.org/api/fs.html 、https://nodejs.org/en/learn/manipulating-files/working-with-file-descriptors-in-nodejs ）。
- 安全研究文章 “Why Secure Filesystem Operations Are Harder Than You Think”（Snyk，2026-03-31，https://snyk.io/articles/safe-path-handling/ ；本次仅取得搜索摘要，原文页面受网络策略限制未能抓取）指出：Node.js 不暴露 `openat()`，`fs` 只按路径解析，纯 Node.js 的 `realpath` + 前缀检查仍有竞态；安全方案需要 native addon 或平台特定能力。
- GitHub/npm 搜索（2026-10-27）未发现官方 Node `openat`/`renameat` API；目录句柄类候选：
  - `@openclaw/fs-safe`（npm，搜索摘要：Node ≥22、Rust native、Linux 使用 openat2，其他平台为受保护/尽力而为实现）——**macOS 是否具备同等原子 dirfd 语义未能独立核实**。
  - `@cocalc/openat2-linux-x64-gnu` 等（npm，搜索摘要：Linux openat2 专用）——**不覆盖 macOS**。
- 以上候选均未在仓库安装或运行；本阶段禁止新增依赖，因此不构成可实施证据。

## 4. 需求与能力的差距

Artifact 大文件流程要求：

1. 以已授权 `root_path` 为锚，逐组件打开父目录；
2. 所有 create/rename/unlink 相对已锚定目录句柄执行；
3. 每级 no-follow，拒绝 symlink/traversal；
4. 校验后不得改用未锚定绝对路径。

Node 22 核心只满足「打开目录 fd」，不满足 2、3 的原子组合；`realpath` + 绝对路径 I/O 明确被计划禁止作为 fallback。

---

## 5. 解除阻断的条件（供用户决策）

任一路径满足后才可重新评估 Artifact 文件写入：

1. 批准引入受维护的 dirfd-relative 实现（native addon 或等价），并在 Node 22/macOS 上用独立测试证明：
   - 父组件在校验后替换为 symlink 时，create/rename/unlink 仍被拒绝；
   - 逐组件 no-follow；
   - 原子 rename 与 fsync 语义；
2. 或采用不依赖文件系统的手动 artifact 方案（例如仅 inline 且上限内），并重新修订产品范围与容量契约；
3. 或明确接受受限的安全边界（需用户书面接受，且不得声称已证明 TOCTOU 防护）。

在上述决策前：

- 不实现 Artifact 文件写入；
- 不安装 `@openclaw/fs-safe` 或其他 native 依赖；
- 不提供 `realpath` 后绝对路径 I/O 的降级路径；
- SQLite inline Artifact 不受 dirfd 门阻断，但仍受 Workspace `root_path` 前置与阶段门约束；本轮不实现。
