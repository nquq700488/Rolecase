# 模块边界与升级规则

> 所属项目：Rolecast
> 目标：保证模块可以独立替换、升级和测试，不把实现细节泄漏到整个项目。

## 1. 总原则

1. 领域模型不依赖外部框架；
2. 外部系统通过 Port 接入；
3. 任何跨层调用都经过明确的 Application Service；
4. 前后端只通过 Contract 通信；
5. 模块之间传递不可变对象；
6. 配置、凭据、运行状态分开存储；
7. 一个模块只能拥有自己声明的状态；
8. 模块升级必须有契约测试和迁移说明。

## 2. 依赖图

```text
apps/web
   ↓
web ─────→ http/ws ─────→ application ─────→ domain
  │            │               │              │
  └────→ contract              └────→ ports ←─┘
                                      ↑
                         infrastructure implementations
```

箭头表示“调用或依赖”。Infrastructure 实现 Port，Application 只依赖 Port。

允许的依赖：

```text
web          → contract, platform-host, Vue 3 / Vue Router / Pinia / Naive UI / UnoCSS / axios / Zod
http/ws      → contract, application, Fastify（唯一允许依赖 Web 框架的模块）
application  → domain, application ports
infrastructure → domain/application ports, external SDKs
main.ts      → 全部模块（仅装配，不含业务逻辑）
```

禁止的依赖：

```text
domain → HTTP、ACP、SQLite、Vue、Node process API
domain / application / contract → 任何 Web 框架（Fastify、NestJS、Express）
application → 装饰器 DI 框架（NestJS、TypeDI 等）
web → Tauri/Electron、SQLite、ACP
orchestration → claude-acp/codex-acp 具体包
http → 直接 SQL
Role → credential 原文
```

### 2.1 目录布局与装配层

```text
apps/
└── web/                  Vue 3 + Vite + UnoCSS + Naive UI
    ├── pages/            路由页面
    ├── components/       可复用组件
    ├── stores/           Pinia
    ├── api/              网络层封装（axios 实例 + WebSocket 客户端 + Zod 校验）
    └── platform/         PlatformHost 的 Web 实现
packages/
├── contract/             共享 DTO 与事件 Schema，禁止任何框架
└── server/
    ├── domain/           领域模型，禁止任何框架与 I/O
    ├── application/      用例 + application/ports/，禁止任何框架
    ├── http-ws/          唯一允许依赖 Web 框架的目录
    ├── infrastructure/   Port 实现（ACP / SQLite / Keychain / EventBus / Config）
    └── main.ts           composition root
```

装配层规则：

- `main.ts` 是唯一创建具体实现并注入依赖的位置；
- 装配层只做「创建实现 → 注入 → 启动」，不含业务判断；
- 装配层是依赖注入的落点，不使用装饰器或运行时反射；
- 新增 Port 或替换实现时，只修改装配层，不修改 `application` 与 `domain`。

## 3. Port 规则

Port 是稳定边界，统一定义在 `application/ports`；Domain 只依赖这些抽象，不定义基础设施实现：

```text
AgentRuntimePort
CapabilityDiscoveryPort
ContextBuilderPort
RepositoryPort
CredentialStorePort
SecretRedactionPort
WorkspaceConfigPort
RoleConfigRepositoryPort
EventBusPort
EventStorePort
ClockPort
IdGeneratorPort
```

实现位于 `infrastructure`：

```text
AcpAgentRuntime
SqliteRepositories
KeychainCredentialStore → CredentialStorePort
InProcessEventBus      → EventBusPort
SqliteEventStore       → EventStorePort
```

CredentialStore 原文只允许在 ACP Runtime Infrastructure 的 Adapter spawn 边界读取；Application、Domain、HTTP 和 Web 只传递 credential_ref，不能获取 Secret。ACP payload 在进入 RuntimeEvent 前执行防御性脱敏，Application 在持久化/发布前再次脱敏；Runtime 不把 Secret 原文放入 Context 或事件对象。

Secret 的精确子串匹配由 `SecretRedactionScope` 承担：只在一次 Adapter 连接期间持有原文，不序列化、不写日志、不进入事件；`connect` 的任何失败路径、`closeConnection` 与 Adapter 异常退出都必须走同一个幂等清理并 `close()`。Runtime Context 只持有该 scope 对象本身，不保存 Secret 原文字段或可序列化 matcher。`credential_ref` 只与 `isolated` 环境配对，`inherited` 连接携带引用必须显式报错而不是静默忽略。Runtime 的**成功响应结构**（能力快照、Session 配置选项、模型目录）与**错误 message/data** 同样必须先经 scope 脱敏才能离开 Infrastructure。

Provider 连接的 `provider_kind × connection_kind × environment_mode × 引用/URL/配置` 组合由 Application 的 `resolveProviderCombination` 单点判定，`testConnection`、`discoverModels` 与 Session 创建共用；Runtime 在 spawn 前再做一次防御性校验。判定结果 `unverified` 表示「endpoint 覆盖已证实、认证未证」，必须 fail-closed，不得当作 ready——目前仅 Codex custom endpoint 属于此类。

上层只能依赖接口，不得依赖实现类。实现可以替换而不修改用例。

### 3.1 第一阶段 Port 最小契约

以下是第一阶段实现必须保持的最小方法边界。具体 TypeScript 类型定义位于 `packages/contract` 与 `packages/server/application/ports`；这里定义语义，不复制实现代码。

```text
AgentRuntimePort
  connect(connection) → RuntimeConnection
  createSession(input) → RuntimeSession
  sendTurn(input) → RuntimeEvent stream
  setConfigOption(session, configId, value) → RuntimeSession
  respondPermission(input) → void
  cancelTurn(input) → void
  resumeSession(input) → RuntimeSession
  closeSession(input) → void

CapabilityDiscoveryPort
  discover(connection) → CapabilitySnapshot

SecretRedactionPort
  fingerprint(secret) → string
  redact(value) → string
  redactRecord(value, secretFingerprints?) → value
  createScope(secret) → SecretRedactionScope
    redact / redactValue / redactStreamRecord / dropStream / close
    flushStream(streamId) → { path, text }[]（按字段路径返回，调用方不得跨路径拼接）

RepositoryPort
  get(entity, id) → Entity | null
  list(query, cursor) → Page<Entity>
  save(entity) → Entity
  delete(entity, id) → void
  transaction(operation) → Result
  listPendingPermissions(now) → PermissionRequest[]

EventBusPort
  publish(event) → void
  subscribe(filter, handler) → Subscription

EventStorePort
  append(event) → sequence
  replay(runId, afterSequence) → Event[]

ClockPort / IdGeneratorPort
  now() / nextId() → value
```

契约约束：

- Port 输入输出只能使用 Domain 值对象、Contract 映射对象或明确的 Runtime 类型，不得暴露 Fastify、SQLite、ACP 帧或 Vue 类型；
- `resumeSession` 失败必须返回可分类错误，Application 不得静默新建 Session；
- `SecretRedactionScope` 的生命周期不得长于一次 Adapter 连接；所有退出路径都必须 `close()`，`flushStream` 只交还 Secret 真前缀，`dropStream` 丢弃窗口；
- `transaction` 必须覆盖 PermissionRequest 与 Run/Task 的联合状态变更；
- `listPendingPermissions` 必须支持服务重启后的软/硬超时恢复；
- 所有 Port 都必须有 Fake Contract Test，替换实现不能修改 Application 用例。

## 4. 模块能力卡片

每个模块的 README 必须说明：

- 目标；
- 提供的能力；
- 不提供的能力；
- 公共接口；
- 输入、输出和错误；
- 状态和不变量；
- 允许和禁止的依赖；
- 持久化；
- 事件；
- 安全边界；
- 升级方式；
- 测试方式；
- 已知限制。

模块文档模板见本文末尾。

## 5. 替换规则

### 5.1 替换 Adapter

新增 Adapter 必须实现 `AgentRuntimePort`，并通过相同的 Contract Test：

```text
initialize
create_session
send_turn
stream_events
request_permission
cancel_turn
resume_session
close_session
crash_recovery
```

Orchestration 不得为新 Adapter 增加分支逻辑。

### 5.2 替换数据库

Repository 实现可以从 SQLite 替换为其他数据库，但必须保持：

- 查询结果语义一致；
- 事务边界一致；
- 分页游标稳定；
- 并发状态转换一致；
- 迁移和备份策略明确。

### 5.3 替换凭据存储

Keychain 可以替换为开发环境的 0600 文件存储，但 `CredentialStorePort` 的调用者不能知道存储位置，也不能获得持久化文件路径。

### 5.4 替换前端

Vue Web UI 可以替换为其他客户端，只要遵守 HTTP/WS Contract。任何客户端都不得直接依赖内部 Domain Entity。

### 5.5 替换 HTTP 框架

`http-ws` 是唯一允许依赖 Web 框架的模块。替换 Fastify 时：

- 只修改 `http-ws` 与 `main.ts`，不触碰 `application`、`domain`、`contract`；
- 必须保持 REST/WS Contract、错误码、鉴权行为和事件 envelope 不变；
- 若引入装饰器框架（如 NestJS），仍需遵守本节边界：框架只允许出现在 `http-ws` 与装配层。

## 6. 版本规则

- API Schema 使用 `schema_version`；
- 事件在同一 Run 内使用单调递增 `sequence`；
- 删除字段先标记 deprecated；
- Adapter 使用 lockfile 精确版本；
- 数据库使用显式 migration version；
- 模块行为变化必须写 ADR；
- 不允许用“兼容一下”的隐式字段猜测代替迁移。

## 7. 事务规则

以下操作必须具备明确事务边界：

- Task 状态与 Task Event；
- Artifact 元数据与 Task 输出关联；
- SessionAgent 创建与 Session 索引；
- Run 终态与失败原因；
- Credential 引用变更与配置版本；
- Role / RoleBinding 的 Workspace JSON mutation：读取、引用检查、CAS 和原子写入必须在同一受控临界区内完成。

跨模块事务通过 Application Service 编排，不能让两个基础设施模块互相调用。
